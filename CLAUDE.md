# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Proyecto

Arcade Vault: plataforma para jugar online y competir por la mayor cantidad de puntos. Según el README, se desarrolla con Spec Driven Design (comandos `/spec` y `/spec-impl`, skills de `Klerith/fernando-skills`). Actualmente el código es el scaffold de Create Next App sin lógica propia (`app/page.tsx` es la plantilla por defecto).

No hay framework de tests configurado.

## Skills

Usa siempre /frontend-design para diseñar interfaz de usuario.

## Arquitectura / advertencias

- **Next.js 16.4 + React 19.3** con App Router (`app/`). Esta versión tiene cambios incompatibles respecto a lo que se conoce: antes de escribir código, leer la guía relevante en `node_modules/next/dist/docs/` (`01-app`, `02-pages`, `03-architecture`, `04-community`) y respetar los avisos de deprecación (así lo exige `AGENTS.md`).
- `next.config.ts` activa flags experimentales/no estándar: `cacheComponents: true`, `partialPrefetching: true`, `experimental.agentFeedback`. `cacheComponents` cambia el modelo de caché/renderizado (datos dinámicos y Suspense), así que consultar la doc antes de hacer fetching.
- **Tailwind CSS v4** se procesa vía `@tailwindcss/turbopack` configurado en `turbopack.rules` de `next.config.ts` (no hay `postcss.config`). Los tokens de tema están en `app/globals.css` (`@import "tailwindcss"` + `@theme inline`, modo oscuro por `prefers-color-scheme`).
- **Supabase** (proyecto `rvdlyinimpdntwggwrew`, esquema `public` con `games` y `scores`): `lib/supabase/client.ts` (`createBrowserClient`, para Client Components) y `lib/supabase/server.ts` (`createServerClient`, `async`, usa `await cookies()`, así que solo dentro de `<Suspense>` por `cacheComponents`). Ambos se crean por llamada, van tipados con `Database` de `lib/supabase/database.types.ts` (generado con el MCP `generate_typescript_types`; regenerarlo tras cada cambio de esquema) y lanzan un error que nombra la variable si falta alguna. Variables en `.env.local` (plantilla en `.env.example`): `NEXT_PUBLIC_SUPABASE_URL` y `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`. Solo esas llevan `NEXT_PUBLIC_`; `SUPABASE_DB_PW` y `service_role` nunca van al cliente. Toda tabla nueva se crea con RLS activado. `SessionProvider` y las puntuaciones de los juegos sin motor siguen en `localStorage` (`av_scores`) hasta el spec de auth.
- **Leaderboard (SPEC 06)**: tablas `games` (`id`, `title`, `cat`, `ranked`, `sort_order`; el `id` es el slug de `lib/games.ts`) y `scores` (una fila por partida: `game_id`, `player_name` 3–12 caracteres en mayúsculas, `score` 1–10 000 000), ambas con RLS. `anon` y `authenticated` leen ambas e insertan en `scores` solo si el juego tiene `ranked = true`; no hay `UPDATE` ni `DELETE`, y `games` solo cambia con migraciones (`supabase/migrations/`). Vistas con `security_invoker = true`: `game_stats` (`best` y `plays` por juego, 0 si no hay partidas) y `global_leaderboard` (suma de la mejor marca de cada nombre por juego). Las lecturas están en `lib/supabase/queries.ts` (`getGameLeaderboard`, `getGlobalLeaderboard`, `getGameStats`; cliente de servidor, Top 50, lanzan si Supabase falla, así que van dentro de `<Suspense>` con `try/catch` en la página). `lib/games.ts` ya no tiene `best` ni `plays`: salen de `game_stats`. Rutas: `/salon` (global) y `/salon/[id]` (por juego); `proxy.ts` responde 404 a cualquier `/salon/<id>` que no esté en `ENGINES` (sin él, la primera petición a un id inexistente devolvía 200 por el streaming de `cacheComponents`). El spec de auth deberá fusionarse con ese `proxy.ts`, solo se admite uno.
- **Juego nuevo con motor y ranking**: además de lo descrito en "Juegos con motor", hay que poner `ranked = true` en `games` con una migración. `ranked` (base de datos) y `id in ENGINES` (código) deben coincidir; si no, el RLS rechaza el guardado o la UI enlaza a un ranking vacío. Limitación aceptada: el nombre es texto libre sin identidad ni antitrampas hasta el spec de auth.
- **Juegos con motor** (`lib/games/`): `types.ts` define el contrato `GameEngine` (`start`/`pause`/`resume`/`restart`/`end`/`destroy`) y los callbacks `onStats`/`onGameOver`; `registry.ts` asocia el `id` del juego con su fábrica en `ENGINES`. `lib/games/asteroids/` (`engine.ts`, `entities.ts`, `constants.ts`) es el primer motor: TypeScript puro, sin `document` ni globals, y el estado vive en la instancia. `components/game-canvas.tsx` monta el canvas 800×600 y destruye el motor al desmontar; `GamePlayer` usa `GameCanvas` si `game.id in ENGINES` (HUD, pausa y modal de la plataforma; el motor solo emite datos) y mantiene la arena mock para los demás. Un juego nuevo = su carpeta en `lib/games/<id>/` + entrada en `ENGINES` + entrada en `lib/games.ts` (y en `CONTROLS` de `game-player.tsx` para la leyenda de teclas).
- `app/layout.tsx` usa el tipo global `LayoutProps<"/">` (tipos de rutas generados por Next) y las fuentes Geist vía `next/font/google`.
- `AGENTS.md` es regenerado por `next dev`; no tiene sentido quitarlo de un diff.
